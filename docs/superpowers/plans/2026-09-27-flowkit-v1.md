# Flowkit v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `@flowkit/*` — a TypeScript library for defining workflow nodes/plugins, editing tree-shaped workflows on a React Flow canvas, and executing them durably with an audit trail — plus two example apps.

**Architecture:** pnpm monorepo. `core` (pure, isomorphic: definitions, doc model, refs, validator, manifest, client) → `nodes-builtin` → `engine` (durable interpreter over a `StorageAdapter`, workers, HTTP handler) → storage adapters. `react` consumes only `core` + the JSON manifest over HTTP. Examples wire everything together.

**Tech Stack:** Node 22, pnpm 10, TypeScript 5.x strict, Zod 4 (`z.toJSONSchema`, `.meta()`), Vitest 3, tsup, Biome, React 19, @xyflow/react 12, Zustand 5, Radix UI primitives, cmdk, CodeMirror 6, lucide-react, quickjs-emscripten, cron-parser, pg + @electric-sql/pglite (tests), Hono + @hono/node-server, Vite 6, Playwright.

**Spec:** `docs/superpowers/specs/2026-09-27-flowkit-design.md` (read it first). UX research: `docs/research/canvas-ux.md` (required reading for Tasks 13–16).

## Global Constraints

- Package scope `@flowkit/*`; all packages ESM-only, `"type": "module"`, TS `strict: true`, `noUncheckedIndexedAccess: true`.
- Workspace dev resolution: each package's `exports` points at `./src/index.ts` (types + default); `publishConfig.exports` points at `./dist/*`. No build step is required for tests/examples; `pnpm build` (tsup) must still succeed for every package.
- `@flowkit/core` and `@flowkit/react` must never import from `@flowkit/engine`, `nodes-builtin`, Node built-ins, or anything server-only. The browser only ever sees the **manifest** (JSON).
- Step IDs match `/^[A-Za-z_][A-Za-z0-9_]*$/` and are unique per doc. Workflow IDs match `/^[a-z0-9][a-z0-9-_]*$/`.
- Timestamps inside engine/storage are epoch milliseconds (`number`). The engine gets time only from an injectable `clock: () => number`.
- Secrets never appear in workflow docs, journals, or events.
- Every public export has TSDoc.
- Commits: conventional commits, end every message with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`. Work on branch `flowkit-v1`.
- Commands must pass before a task is done: `pnpm -r typecheck`, `pnpm test`, `pnpm lint`.

## Plan refinements vs spec (decided while planning; the spec is updated accordingly)

1. **Validator operates on the manifest** (JSON Schema), not on Zod objects, so the same code runs in the browser. `validateWorkflow(doc, manifest, ctx)`.
2. **`summary` is a template string** (`"Load contact {{contactId}}"`) rendered against config, not a function — it must be serializable into the manifest.
3. **Resumable handlers:** a handler that suspended is re-invoked on resume with `ctx.resume` set (`timer | callback | timeout | subflow | subflowFailed`). This is how `delay`, `waitForCallback`, and `callSubflow` produce their final output.
4. **One atomic storage write:** `StorageAdapter.commit(lease, patch, events)` replaces the spec's separate commitStep/suspendRun/failRun/completeRun/releaseRun.
5. **forEach output** is `{ count: number, results: unknown[] }` (results = last body step output per iteration).
6. **HTTP client** lives at `@flowkit/core/client` (isomorphic `fetch`), so headless consumers and `react` share it.
7. **Postgres tests use PGlite** (in-process WASM Postgres); a real server is used when `FLOWKIT_PG_URL` is set. Docker is not assumed.
8. **Schedules** need no extra table: `engine.tickSchedules()` computes the latest due fire time per published schedule workflow and starts a run guarded by `recordDedupeKey("schedule:<wf>:<fireTs>")`.

## Review Focus

1. **Upstream step deleted/renamed/retyped while referenced downstream** → validator reports `ref.unresolved`/`ref.typeMismatch` on the referencing field, the editor shows a warning pill + card badge, and `publish` is rejected server-side. (Tests in Task 4 and Task 15.)
2. **Editing/publishing a workflow while runs are in flight** → in-flight and waiting runs keep executing their pinned version; new runs use the new published version. (Test in Task 8.)
3. **Duplicate deliveries** (webhook retried by sender, event emitted twice with same dedupeKey, resume URL hit twice) → exactly one run / one resume; second resume returns HTTP 410. (Tests in Tasks 9 and 11.)
4. **A reference resolves to `undefined`/`null` at runtime** (optional CRM field empty) → templates render empty string; a required input that resolves to undefined fails the step *fatally* with a message naming the field and the ref path, visible in the run viewer. (Test in Task 7.)
5. **Tenant isolation** → tenant A cannot list/read/retry/resume-by-id tenant B's workflows or runs through the handler or engine API. (Test in Task 11.)

Also exercised: forEach over an empty array (body skipped, `count: 0`); switch value matching no case (→ `default`); disabled steps (skipped, recorded as `skipped`).

```ts
function walk(steps: Step[], prefix: string): NextAction | null {
  for (const step of steps) {
    const path = prefix + step.id;
    const e = journal[path];
    if (step.disabled) { if (!e) return { type: "skip", step, path }; continue; }
    if (e?.status === "done" || e?.status === "skipped") continue;
    const node = registry.getNode(step.type)!; const bk = node.branches?.kind ?? "none";
    if (e?.status === "branched") {
      const r = walk(step.branches?.[e.branch] ?? [], `${path}/${e.branch}/`); if (r) return r;
      return { type: "completeBlock", step, path };
    }
    if (e?.status === "looping") {
      for (let i = 0; i < e.items.length; i++) { const r = walk(step.branches?.body ?? [], `${path}/body[${i}]/`); if (r) return r; }
      return { type: "completeBlock", step, path };
    }
    return { type: "exec", step, path, scopeFrames: framesFor(path) };   // no entry, suspended, or failed-with-retry
  }
  return null;
}
```
Executor `runOnce`: claim → load pinned `WorkflowVersion` (cache by `${tenant}:${wf}:${v}`) → loop up to `stepsPerClaim` (default 100):
1. `nextAction`. `complete` → evaluate `doc.output` mapping (resolve against end scope), commit `status: completed, output, release`, event `run.completed`; if `run.parent` → `storage.resumeRun(parent.runId, parent.stepPath, {kind:"subflow", output})`. Return.
2. `skip` → commit journal `{status:"skipped"}` + `step.skipped`.
3. `completeBlock` → for branched: `{status:"done", output: e.output, branch}`; for looping: `{status:"done", output:{count, results}}` where results[i] = output of last non-skipped body step in iteration i (or `null`).
4. `exec`: build scope → `resolveValue` for each config key → `node.input.safeParse(resolved)`. Failure → **fatal** error, message `Step "<name|id>": field "<key>" <zod message> (from <ref path or 'literal'>)` (Review Focus #4). Emit `step.started` (data: redacted input). Call `run({ input, ctx })` with `AbortSignal.timeout(node timeout default 5 min)`. Handle result:
   - plain output → validate against `node.output` if present (fatal on failure) → journal `done` (branch nodes of kind `static`/`fromConfig` must return a `branch()` signal; plain output for them is a fatal error `"must return branch()"`).
   - `branch(id, output)` → check id ∈ `branchesFor(manifest, step)` else fatal → journal `branched` (or `done` + `branch` if branch has zero steps — walk handles either).
   - loop node (`kind: "loop"`): handler returns output `{ items: unknown[] }` → journal `looping` with items, results [].
   - `stop(reason)` → journal `done` output `{ stopped: true, reason }`, commit run `completed` with `output: { stoppedAt: path, reason }`, event `run.stopped`. Return.
   - `suspend`/`invokeSubflow` → Task 8 (for now throw `FatalError("not supported")`).
   - throws `FatalError` or validation failure → journal `failed`, run `failed`, events `step.failed` + `run.failed`.
   - throws other → if `attempt < retry.max` → commit `status: waiting, wakeAt: now + backoff(attempt), attempt: attempt+1, release`, event `step.retrying {attempt, delayMs, error}`; else fail as above. Backoff: fixed = initialMs; exponential = initialMs * 2^(attempt-1), cap 1h. Defaults `{max:3, backoff:"exponential", initialMs:1000}`. `attempt` resets to 1 when a step completes.
   Every commit that returns false (lease lost) → stop processing silently.
5. After `stepsPerClaim` → commit `status: queued, release`.
Idempotency key: `sha256(runId + ":" + path)` hex (use `crypto.subtle` via `globalThis.crypto`). Redaction: remove values for properties whose manifest `x-flowkit.secret|sensitive` is true (replace with `"[redacted]"`) from `input` in events and journal, then apply `opts.redact`. `ctx.scope` is a deep-frozen copy.
